# S11: Reproducible build pipeline

Fixes **C07** (no script built `payload\`; the shipped Setup.exe matched no commit) and the runtime
part of **C28** (bundled Python not isolated). Verifies **H16** and **H17**.

## What was added

| File | Purpose |
|---|---|
| `VERSION` | Single source of the version number (`1.1.0`). |
| `build/pins.json` | URL and SHA-256 pins for Python, AutoHotkey, SearXNG and NSIS. |
| `build/requirements-searxng.in` | Upstream `requirements.txt` at the SearXNG pin (it already lists `curl_cffi`), plus `tzdata`. |
| `build/constraints-searxng.txt` | The package versions vendored in v1.0.0 `searxng\lib`, used as constraints. |
| `build/requirements-searxng.txt` | The lock: 32 packages, `--generate-hashes`, cp313/win_amd64, wheels only. |
| `build/lock-searxng.ps1` | Regenerates the lock with `uv pip compile --generate-hashes`. Run it only when bumping a pin. |
| `build/build.ps1` | The build (PowerShell 5.1). |
| `build/smoke.ps1`, `build/h16_probe.py` | The H16 smoke test, run with the payload's own interpreter. |
| `build/.gitignore` | Ignores `cache/` and `out/`. |

**Usage**

```
powershell -NoProfile -ExecutionPolicy Bypass -File build\build.ps1 -SkipInstaller -AllowMissingNotices
```

**Switches**
- `-SkipInstaller`: no NSIS.
- `-AllowMissingNotices`: not for releases; tolerates missing S12 files.
- `-AllowDirty`: skips the clean-tree check. The payload is still built from `HEAD`.
- `-SkipSmoke`: skips the H16 smoke test.
- `-NsisTarget <t>`: overrides the NSIS target (see the S13a hand-off below).
- `-HostPython <exe>`: the interpreter that runs `pip download`. Any Python with pip works.

**Build steps**
1. Require a clean tree.
2. Download and verify every pin; any SHA-256 mismatch fails the build and the file is renamed to `*.bad`. This was tested.
3. `pip download --require-hashes --no-deps --only-binary=:all:` the locked wheels, then re-check each wheel's name, version and hash against the lock independently of pip.
4. Export the sources with `git archive HEAD`, using `core.autocrlf=false` and `core.eol=lf` so only `.gitattributes` decides line endings, whatever the machine's git config.
5. Assemble the payload from an explicit allowlist:
   - `main.ahk`, `icon.ico`, `config.example.ini`, `LICENSE`
   - root `*.py` except `test_*.py`
   - `actions/*.py`, `static/`, `lib/*.ahk` (optional)
   - `searxng/{avvia_searxng.py, settings.yml, LICENSE-searxng.txt}`
   - `THIRD_PARTY_NOTICES.md` and `licenses/` (S12)
6. Add `searx/` from the upstream tarball plus the generated `version_frozen.py`, and unzip the wheels into `searxng\lib`. No pip install, no scripts and no bytecode.
7. Add the embeddable CPython with `python313._pth` (`python313.zip`, `.`, `..`, per D2), plus `AutoHotkey64.exe` and its `license.txt`.
8. Copy `config.example.ini` to `payload\config.ini`.
9. Audit the payload, and fail if it contains any of:
   - `__pycache__`, `work`, `.git*`, `*.pyc`, `*.log` or `*.pid`
   - root `tests`, `plans`, `pyproject.toml`, `scripts`, `tools`, `docs`, `installer` or `test_*.py`
   - an app-level `config.ini`
   - a `config.ini` whose hash differs from `config.example.ini`
10. Set every payload file time to the commit time.
11. Write `build/out/manifest.txt` and `build/out/uninstall.nsh`.
12. Run `tools/licenses/check_notices.py <manifest>`, if S12 has added it.
13. Run `makensis /DVERSION=<VERSION>`.
14. Write `SHA256SUMS.txt`.
15. Run the smoke test.

**Payload layout** (unchanged, so `installer.nsi` needs no edit for it): `payload\{app\, python\, ahk\, config.ini}`. The SearXNG tree lives in `payload\app\searxng\{app,lib}`.

## H17: vendored SearXNG vs upstream `6671d89`: **unmodified**

`diff -rq -x __pycache__` of upstream `searx/` against the vendored `C:\AI-Hotkeys\searxng\app\searx` reports exactly one difference: `Only in vendored: version_frozen.py`. That file is the standard output of upstream's `python -m searx.version freeze`, used for builds outside git. It contains only the version, tag, URL and branch strings.

- **AGPL status:** no patch to carry. Upstream source at the pinned commit is the corresponding source (S12, S14).
- `build.ps1` regenerates `version_frozen.py` byte-identically from `pins.json`. A diff of the built payload's `searx/` against the vendored tree is empty.
- `searxng/LICENSE-searxng.txt` (as committed) is byte-identical to upstream `LICENSE`.

**Locked `searxng\lib` compared with v1.0.0**
- Every file of every shared package is identical, apart from `.dist-info` install metadata.
- `colorama` 0.4.6 is new. It is click's dependency on Windows; v1.0.0 lacked it.
- `async_timeout` was dropped. It is only required on Python < 3.11.3.
- `tzdata` is kept as an explicit AI-Hotkeys addition. SearXNG uses `zoneinfo` (time_zone plugin, weather, bilibili), and Windows has no system tz database.

## H16: embeddable Python with `._pth`

The smoke test copies the payload to `%TEMP%`, sets `PYTHONPATH` to a poison folder, and runs `h16_probe.py` with the payload's interpreter under two variants of `python313._pth`.

| Check | D2 `._pth` (`python313.zip`, `.`, `..`), the one shipped | Minimal (`python313.zip`, `.`) |
|---|---|---|
| `sys.path` | zip, `python\`, install root | zip, `python\` |
| Flags | `isolated=1`, `ignore_environment=1`, `safe_path=True`, `site` not imported | same |
| PYTHONPATH and user site-packages | ignored (C28 fixed at runtime) | ignored |
| Bare `import qwen_client` etc. from a neutral cwd | ok | **ModuleNotFoundError** for all 7 root modules |
| Each entry point main.ahk runs, loaded as main.ahk runs it (as a script in its own folder, cwd = install root) | ok; every app module resolves to the install root | ok |
| `viewer.py` → `websearch._cffi()` reuses `curl_cffi` from `searxng\lib` | ok | ok |
| SearXNG import (launcher path setup + `from searx import webapp`) | ok, 695 modules, **no app module imported**, nothing loaded from outside the payload | ok |
| Static scan: root names imported by `searx`/`lib`, provided by `lib`, or stdlib names | none | none |
| `avvia_searxng.py` on a free port, temp `work\` → `/healthz` | **200 after 3.1 s** | n/a |

The entry points tested were the five `actions/*.py`, `viewer.py`, `settings.py`, `config_edit.py` and `searxng/avvia_searxng.py`.

**Verdict**
- **H16 "sibling imports fail without `..`" is refuted for the real entry points.** In `._pth` mode `safe_path` is on, so the script's folder is not prepended. Every entry script inserts its own folder or the root into `sys.path` itself.
- `..` is only needed for bare imports such as `python -c "import qwen_client"`, i.e. tooling.
- **H16 "`..` causes shadowing" is refuted.** No collision exists between root names (`actions`, `config_edit`, `pages`, `prompts`, `qwen_client`, `settings`, `viewer`, `websearch`, `searxng`, `static`, `python`, `ahk`) and anything SearXNG, its libraries or the stdlib import.
- D2 stands as shipped.

**Notes for S8b2**
- Under `._pth`, the interpreter already runs isolated and ignores the environment, so `-E -s` is redundant but harmless.
- `..` puts the install root on `sys.path` for every process, SearXNG included. That is one more reason the install folder needs the private ACL (C09/S13a).

## Reproducibility

- Repeated builds from the same commit on the same machine gave identical results:
  - `manifest.txt`: `9e2d6709…f9ed61` and `uninstall.nsh`: `96263068…87701c`, identical in all 4 runs
  - `AI-Hotkeys-Setup-1.1.0.exe` (`-NsisTarget x86-unicode`): `88f61b85…141bf4`, byte-identical in both installer runs
- The `.exe` is byte-identical because NSIS stores file times, and the build pins them to the commit time.

## Hand-offs

- **S13a (`installer.nsi`)**
  - `Target amd64-unicode` cannot be built with the official NSIS. The official zip ships only x86 stubs, and the v1.0.0 Setup.exe is PE32+, so it was built with a non-official amd64 NSIS.
  - Recommendation: `Target x86-unicode`. A 32-bit installer installs the x64 payload fine; `stop.ps1` uses CIM, which works across bitness; HKCU keys are not redirected.
  - Until then, `build.ps1` fails with this explanation unless `-NsisTarget x86-unicode` is passed. The override applies only to the staged copy.
  - `!define VERSION "1.0.0"` must become `!ifndef VERSION`/`!define`/`!endif`. Until then, `build.ps1` wraps it in the staged copy, with a warning.
- **S13b**
  - `build/out/uninstall.nsh` defines `!macro AIH_UNINSTALL_PAYLOAD`. It:
    - deletes every payload file except `config.ini`
    - runs `RMDir /r` on `__pycache__` in every folder that holds `.py` files
    - then runs a plain `RMDir`, deepest folder first
  - `build.ps1` copies `installer/sorgente/*.{nsi,nsh,ps1,manifest}` next to `payload\` and compiles there, so `!include "uninstall.nsh"` resolves.
- **S12**
  - Manifest format: one `<sha256>  <install-relative path, forward slashes>` per line, ordinal-sorted, `#` comment header.
  - `build.ps1` runs `tools/licenses/check_notices.py build/out/manifest.txt` automatically once it exists. It is blocking unless `-AllowMissingNotices` is passed.
  - The redistributed set to cover:
    - CPython 3.13.16 (embeddable, including the OpenSSL/libffi/sqlite DLLs)
    - AutoHotkey 2.0.19
    - SearXNG `6671d89`
    - the 32 locked wheels, including `curl_cffi.libs/libcurl-impersonate-*.dll`
    - marked
    - the fonts
- **S14**
  - CI needs Windows PowerShell 5.1, git, `tar.exe` and a Python with pip.
  - Cache `build/cache/` keyed on `pins.json` + `requirements-searxng.txt`.
  - Attach the pinned SearXNG tarball and the AHK source zip as AGPL/GPL source offers.
- **H27**
  - `pip-audit -r build/requirements-searxng.txt` was not run here, because it queries an external vulnerability service. Leave it to S2/S14 CI.
