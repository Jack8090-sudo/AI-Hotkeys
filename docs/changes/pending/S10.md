# S10 — UI/UX and accessibility of the local pages

Fixes C34, C40 and the UI part of C33. Files: `static/viewer.html`, `static/settings.html`,
`static/theme.css`, plus the §8 one-line insert of `("searxng", "query_mode")` into `settings.py`
`CHOICES` (with a test in `tests/test_settings_validate.py`). The `<title>` patterns
"… - AI-Hotkeys" and "AI-Hotkeys Settings" are unchanged (S8b1 relies on them).

User-visible:
- Settings, Keys: each key box has a name that says the action and the current key
  ("Fix key: PgUp. Press Enter to change it."). A screen reader announces "listening", the new
  key, and errors. Errors are linked to the box (`aria-invalid`, `aria-describedby`). Each
  "Default" button has its own name ("Restore the default Fix key (PgUp)").
- Tab and Shift+Tab always leave the key box and are never recorded. Ctrl+C, Ctrl+V, Ctrl+X,
  Ctrl+Z, Ctrl+A, Alt+F4 and Alt+Tab are refused with a reason. AI-Hotkeys itself copies the
  selection with Ctrl+C.
- Settings, Web search: a "What leaves this PC" notice says that the search words go to Startpage
  and Yahoo and that the pages found are downloaded (C33, D5). There is a new "Search words"
  choice for `[searxng] query_mode`: "Qwen or from the text" (`allow_fallback`, the default) or
  "Only Qwen's" (`model`). The S6b backend reads it. When the key is missing, the default applies (I11).
- Settings, validation: messages say what format is expected (for example
  `qwen3.5:9b`, `http://localhost:11434`). Text fields are checked before saving, and the focus
  goes to the first invalid field.
- Settings, Ollama address on another computer: the S7 `warning` is shown in the save bar and
  under the field ("Warning: … the text you select will be sent there"). The same note appears
  when the page opens with a non-local address.
- Results page: the answer area is `aria-busy` while Qwen writes. "Answer ready." (or "New version
  ready: vN.") is announced when it finishes. Errors go to a separate `role="alert"` line.
- The question field is `readonly` + `aria-disabled` while busy, not `disabled`. It keeps the
  focus. Esc stops the answer and no longer blurs the field.
- A K4 `partial: true` answer stays visible and ends with "Incomplete answer. Ollama stopped
  before the end: ask again …". In fix mode the incomplete draft is not saved as a version, and
  the message says so.
- "Disconnected" banner on both pages when the ping fails or returns 403, or the server is gone.
  F5, Ctrl+R and Ctrl+F5 are intercepted and explain that a reload would disconnect the page,
  because the token was removed from the address by S7. Limit: the browser toolbar's reload
  button cannot be intercepted. It still lands on the server's plain 403 page. A friendlier 403
  body would be a server change (viewer.py/settings.py, S9 or a follow-up).
- Contrast: control borders now use a new `--edge` token, at least 3:1 in every theme. The
  selected item of a group has an accent bar and a bold label (a shape, not only colour). The
  selected swatch has a check mark and an underlined label. The colour swatches show the colour
  of the current theme, so light accents in the light theme. Swatches use `data-accent` instead
  of inline `style`.
- Windows high contrast: `forced-colors` rules for the selected state, switches, swatches, key
  caps, the progress bar, the cursor and the banners.
- Layout: `scroll-padding-bottom` keeps the focused field above the sticky question bar and save
  bar. Below 640 px wide or 560 px high (for example 400% zoom), the question bar, save bar and
  preview scroll with the page. The composer textarea has `min-width: 0`. There is no horizontal
  scroll at 320 px.
- Markup: on the results page the result comes first in the DOM. The "Selected text" column is
  still shown on the left, and its `aside` is labelled. Citations have
  `aria-label="Source N: host"`. Follow-up turns and their Copy buttons are numbered ("Copy answer
  2"). The settings preview is `aria-hidden`. Steppers are labelled groups with specific button
  names. Both pages have `<link rel="icon" href="data:,">`, so there is no favicon 404 in the
  console.

Internal (C40): streaming renders at most once every 150 ms. Text up to the last blank line
outside a code fence is rendered once and kept. Only the paragraph being written is re-parsed.
There is a single full render at the end. Pending renders are cancelled before the final, stop
or error render.

## Verification (temp copy of the app, never the real `work/` or `config.ini`)

Setup:
- The root `*.py`, `static/` and `actions/` were copied to a temp dir with a temp `config.ini` and
  input/output files. viewer.py and settings.py ran with `--no-browser`. A streaming fake Ollama
  ran on 127.0.0.1.
- Chrome is not installed, so the chrome-devtools MCP could not start. Lighthouse
  (the copy bundled in chrome-devtools-mcp 1.10.1, snapshot mode, desktop) and puppeteer were
  driven from node against the installed Brave 1.97 (Chromium 155), headless, with a throwaway profile.
- All servers, Brave and the fake were stopped afterwards.

|---|---|---|---|

| settings | dark (`scuro`) | 100 | 100 |

favicon 404. After, there are no messages, so no CSP violations and no errors. The only message
is the expected `ERR_CONNECTION_REFUSED` from the ping after the test killed the server.

machine, Brave headless, `longtask` observer:

|---|---|---|---|---|

Functional and keyboard walkthrough (puppeteer, results recorded):
- Viewer:
  - While streaming, the field is readonly, keeps the focus, and the answer is aria-busy.
  - At the end, "Answer ready." and the focus is back in the field.
  - A K4 partial answer shows the "Incomplete answer." note and a `role=alert` error.
  - Esc stops the answer and the focus stays on the field.
  - F5 shows the banner and does not reload. A killed server plus a ping shows the "Disconnected" banner.
  - At 320 px the dock is static and there is no horizontal scroll.
  - Tab order: header tools, then the result, follow-ups, suggestions, field and Send. Every
    focused element is inside the viewport.
- Settings:
  - Tabbing through all controls, each focused element is visible above the save bar.
  - In the recorder: Enter starts listening and announces it. Shift+Tab leaves without recording.
    Ctrl+C is refused with `aria-invalid`. F8 is recorded and announced.
  - An invalid model name shows the format message and blocks Save, with the focus moved to it.
  - Saving a LAN Ollama URL with "Only Qwen's" shows the S7 warning in the bar and under the field.
    The temp `config.ini` got `ollama_url = http://192.168.1.5:11434`, `query_mode = model` and `correggi = F8`.
  - F5 and the disconnected banners work. At 320 px the save bar is static with no horizontal scroll.
- Not done: the NVDA spot check (H21). NVDA is not installed on this machine. As a mitigation the
  key box is described by a hidden hint to switch to focus mode (NVDA+Space, JAWS Insert+Z)
  before pressing the new key. H21 stays open for the manual checklist.
- `python -m unittest discover -s tests -t .` passes: 208 tests, 10 skipped, 1 expected failure. `ruff check .` is clean.
