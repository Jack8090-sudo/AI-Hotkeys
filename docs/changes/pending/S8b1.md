# S8b1 — main.ahk: capture, routing and direct replace

Fixes C03, C04 and C05. Decisions applied: D10 (the result stays in the clipboard after a direct
replace, I15) and D12 (ClipWait stays at 2 s by default, now configurable).

## User-visible

- **Holding a key with nothing selected no longer stalls (C03).** A new `capturing` state covers
  the time between the key press and the end of `^c` / `ClipWait`. `busy` is set only once text has
  been captured. `#MaxThreadsPerHotkey 2` lets a second press of the same key run while the first is
  still copying: that press is sent natively (PgDn scrolls) instead of being dropped. Presses of the
  other two keys during capture are also sent natively. The first press with nothing selected is
  still delayed by the ClipWait timeout and then sent natively, as before.
- **New optional key `[comportamento] clip_wait_ms`** (D12). Whole milliseconds, 100 to 10000.
  Missing, empty or out-of-range values use the code default, 2000 (the old value), so nothing
  changes unless the user sets it. S3 data is not available yet, so the default was not lowered.
  `config.example.ini` is not owned by this step: S15 (or the config owner) should document the key
  there, commented out.
- **Consoles never receive `^c` (C03, H02).** A `Console` context comes first in the dispatcher.
  It matches the window classes `ConsoleWindowClass` (conhost: cmd, PowerShell),
  `CASCADIA_HOSTING_WINDOW_CLASS` (Windows Terminal) and `mintty` (Git Bash, Cygwin, MSYS2). All three
  slots route to `native` there.
- **The results page and the Settings page keep native keys (C04).** The title check is one
  function, `IsAppPageTitle`. It matches ` - AI-Hotkeys` followed by ` - ` or the end of the title
  (the browser appends its own name), and `AI-Hotkeys Settings` anywhere (case-insensitive, as
  before). PgUp, PgDn and End now scroll the results page instead of waiting 2 s or re-running the
  action on the page's own text.
  - Guard: windows of the editors in `EDITABLE_APPS` (Notepad, Obsidian, VS Code, Word, Notepad++)
    are never treated as our pages, even when their title matches. Without it, a VS Code window
    titled `main.ahk - AI-Hotkeys - Visual Studio Code` (a folder named AI-Hotkeys) would lose its
    hotkeys.
  - S10 must keep the `<title>` patterns in `static/viewer.html` (`__TITLE__ - AI-Hotkeys`, plus
    `document.title = ui.title + " - AI-Hotkeys"`) and `static/settings.html` (`AI-Hotkeys
    Settings`). The comment on `IsAppPageTitle` points there.
- **A direct replace never pastes into the wrong window or over the wrong text (C05).** The fix
  result is pasted only when all of these hold:
  1. `WinWaitActive` on the starting window succeeds (2 s).
  2. A re-copy (`^c`) of the current selection matches the text that was sent to Qwen. Line endings
     are ignored; everything else must match exactly.
  3. The window is still active right before `^v`.

  Otherwise nothing is pasted. A toast says why ("The window did not come back to the front",
  "The selection changed" or "The window lost focus", followed by "opened in the results page"),
  the result opens in the results page, and the clipboard holds the user's previous content again.
  After a successful paste the result stays in the clipboard (I15, D10), as before.

## Internal

- New pure helpers in `lib/Util.ahk`: `IsAppPageTitle(title)`, `IsConsoleClass(cls)`,
  `ParseClipWaitMs(value, default := 2000)` and `SelectionMatches(original, recopied)`. They are
  covered by `tests/ahk/run.ahk` (291 assertions in total, 0 failures).
- `main.ahk`:
  - `Dispatch` runs `Critical` until `capturing` or `busy` is set, so a second press cannot start a
    second capture in that window. `Critical` is switched off before any `Flash` or `MsgBox`.
  - New `IsOwnPageActive`, `ReplaceSelection` and `OpenResultsPage`. The direct replace logic is now
    in `ReplaceSelection`.
  - Holding Esc for 2 s during capture still registers the cancel: `CheckEscHold` accepts
    `busy || capturing`, and `WaitPid` acts on the request as soon as Python starts.
  - `WatchConfig` also waits while capturing.
- **C41 not done here.** S3 numbers are not available, so the fixed `Sleep 300` after `^v` and
  `Sleep 500` after `^s` are unchanged. Both are marked in a comment.
- `/validate` was run on a copy of `main.ahk` + `lib\` outside the repo (exit 0). `main.ahk` itself
  was never run.

## Manual Windows E2E checklist (plan §7.2 items 2, 3 and 4; Windows 11 and Windows 10)

The agent cannot press hotkeys. Run these on a real desktop with the S8b1 build running.

1. **Default keys (§7.2 item 2, I1, I6).** In Notepad, Notepad++, VS Code, Word and Obsidian (not
   the To-Do note), with `sostituisci_testo = si`:
   - Select one sentence with a typo and press PgUp. The sentence is replaced in place, and Ctrl+V
     elsewhere pastes the corrected text (I15).
   - Select text and press PgDn. The summary page opens. Press End: the explanation page opens. No
     replace happens for either.
2. **Replace with focus stolen (C05).** In Notepad, select a sentence and press PgUp. Within a
   second, click another Notepad window (or Explorer) and leave it in front.
   - Expected: Notepad comes back to the front and the replace happens. If Windows refuses to bring
     it back (the taskbar button flashes instead), the toast "The window did not come back to the
     front — opened in the results page" appears, nothing is pasted anywhere, and the results page
     opens.
3. **Replace with a changed selection (C05).** In Notepad, select a sentence and press PgUp. While
   Qwen works, click somewhere else in the same Notepad text so the selection is gone (or select a
   different word).
   - Expected: the toast "The selection changed — opened in the results page", the text is unchanged,
     the results page opens, and Ctrl+V pastes what was in the clipboard before PgUp.
4. **Nothing selected (§7.2 item 3, I3).** Copy a known word to the clipboard first.
   - In Notepad with a long document and nothing selected: press PgUp, PgDn and End once each. Each
     acts natively after at most about 2 s. Ctrl+V still pastes the known word.
   - Hold PgDn for 3 s with nothing selected. The page keeps scrolling from the first repeat on, with
     no 2 s gap after the first repeat and no "Qwen is still working" toast.
   - Optional: set `[comportamento] clip_wait_ms = 400` in config.ini, wait for "Settings applied",
     and repeat. The first press now acts after about 0.4 s. Remove the key afterwards.
5. **Results page (C04).** Open a long Summary page in Chrome, Edge and Firefox (set each as the
   default browser in turn, or open the printed URL in it).
   - Press PgUp, PgDn and End with nothing selected. The page scrolls at once (no 2 s delay).
   - Select a paragraph inside the page and press PgDn. The page scrolls; no new summary job starts.
   - In the Settings page, recording a hotkey with PgUp still records "PgUp".
6. **Non-editable app (§7.2 item 4).** Select text in a web page in the browser and press PgUp. The
   results page opens with the fix (no replace in the browser).
7. **Consoles (§7.2 item 4, H02).** Run `ping -t localhost` in each of: cmd in conhost, PowerShell
   in Windows Terminal, and Git Bash (mintty). Press PgUp, PgDn and End.
   - Expected: ping keeps running (no `^C`, no "Control-C" line), and the keys act natively (for
     example scrollback in conhost with PgUp). No progress toast appears.
8. **Esc during capture (I5).** In Notepad, select a large block and press PgUp, then immediately
   hold Esc for 2 s. The job is cancelled ("Cancelled" toast), and `work\output.txt` is not created.
9. **VS Code guard.** Open the AI-Hotkeys folder in VS Code (title `<file> - AI-Hotkeys - Visual
   Studio Code`), select a sentence in a comment and press PgUp. The fix still runs and replaces
   the text.
