# S8b3 — main.ahk: error surfacing and UX

Fixes the AHK side of C06, plus C26 and C27. Wires the H24 health check and the D4 "Edit prompts"
target. Reads contracts K1 and K6 (S4). C41 is not done (see below).

## User-visible

- **Failures say what went wrong (C06, K1).**
  - `work\error.txt` is deleted before each selection job.
  - When a job ends without `output.txt`, line 1 of `error.txt` is shown. Examples: "Ollama is not
    running: start Ollama, then try again." / "Model 'qwen3.5:9b' not found: run  ollama pull
    qwen3.5:9b" / "The answer was cut off …" / "The selected text is too long …".
  - The old generic text "Qwen did not respond. Check that Ollama is running and that the model is
    downloaded." is the fallback when `error.txt` is missing or empty.
- **Errors no longer freeze the hotkeys (C27).** Job errors are now non-modal toasts: the start of
  Python, the K1 message, an empty answer, file errors, and the To-Do route's "no result". Each stays
  at least 8 s (longer for long text). Long or multi-line toast text wraps at a fixed width instead
  of making a very wide window.
  - The only job dialog left is the To-Do route's list of failed checks (several lines). `busy` is
    released before it opens, so the hotkeys work while it is up.
  - Tray dialogs (Settings, Free VRAM, Edit prompts, Reload/Exit confirmation) never held `busy`.
- **The progress toast comes back after "Qwen is still working" (C27).** `Flash` remembers the job's
  progress toast (initial text or the latest `status.txt` phase) and redraws it when the flash ends.
  If something else replaced the flash meanwhile (for example a new phase or the job's end), it is
  left alone.
- **Key problems are reported (C26).** Keys are resolved before anything is registered, and one
  startup toast lists the problems:
  - An invalid key (including the ones S8a now rejects, e.g. `pgup`, `Space`, `Esc`) falls back to
    the default (I2): "Fix: "pgup" is not a valid key, using PgUp".
  - A key set for two slots (also `^!r` vs `!^R`) stays with the first slot, in the order Fix,
    Summarize, Explain. The other slot falls back to its default: "Summarize: Alt+Ctrl+R is already
    used by Fix, using PgDn".
  - Keys the user set win over defaults. With `correggi = PgDn` and no `riassumi`, Summarize has no
    key: "Summarize: PgDn is used by Fix: no key".
  - A key AutoHotkey itself refuses falls back to the default if no other slot has it, otherwise
    the slot gets no key.
  - The tray tooltip and toasts show each slot's real key, or "(no key)".
- **Config warnings are shown once per reload (K6).** At startup, `work\config_warning.txt` (left
  by the previous run's actions) is shown and deleted. The health check rewrites it if `config.ini`
  or `prompts_user.py` still has a problem, and that is shown and deleted again, with duplicate
  lines merged into the same toast. At most 3 lines are shown, plus "(+N more)".
  - "Settings applied", key warnings and config warnings share one startup toast: 1.8 s for
    "Settings applied" alone, 10 s otherwise.
- **Health check at startup (H24).** `actions\health.py` runs once in the background. The exit
  code is read through a process handle (`GetExitCodeProcess`) polled every 300 ms, for up to 30 s.
  - On failure, line 1 of `error.txt` is shown (Ollama not running, too old, or model missing),
    joined with the startup toast if that is still up.
  - It stays quiet if a job started meanwhile (that job reports its own errors), or if the check is
    still running after 30 s.
- **"Edit prompts" opens `prompts_user.py`, never `prompts.py` (D4).** If the file does not exist,
  it is created from a header plus a fully commented-out copy of `prompts.py`. The header explains:
  - how to uncomment a whole assignment,
  - the `BASE_RULES` caveat,
  - the fallback to `prompts.py` on errors,
  - "delete this file to go back".

  Checked: the file generated from the real `prompts.py` loads through `prompt_loader` with no
  warning, and every prompt equals the standard one.

## Not done / notes

- **C41 not done.** S3 numbers are not available, so `Sleep 500` after `^s` and `Sleep 300` after
  `^v` are unchanged (the plan requires before/after data).
- `prompts_user.py` is not in `.gitignore` (not owned here). A developer who uses "Edit prompts" in
  the repo checkout should not commit it; the S11 payload excludes untracked files.
- Race noted: `health.py` calls `clear_error()` on success. If a job fails within the health
  check's first seconds, its `error.txt` can be deleted before AHK reads it, and the generic
  fallback text is shown instead. This is harmless and only possible right after startup.
- `config.example.ini` still does not document `[comportamento] clip_wait_ms` (S8b1): S15 / the
  config owner.

## Manual Windows E2E checklist (plan §7.2 items 5, 11 and 12, plus the S8b3 acceptance criteria)

1. **Ollama stopped (§7.2 item 11).** Quit Ollama (tray, then Quit), then start AI-Hotkeys.
   - Within a few seconds a toast says "Ollama is not running: start Ollama, then try again."
   - Select text in Notepad and press PgDn. The same specific message appears as a toast.
   - While the toast is up, press PgUp/PgDn/End in another app with nothing selected: they act
     natively (the hotkeys are not blocked).
2. **Model missing.** Set `model = qwen-does-not-exist` in `config.ini [qwen]`. After "Settings
   applied", the health toast says "Model 'qwen-does-not-exist' not found: run  ollama pull …". PgDn
   on a selection shows the same. Restore the model.
3. **Too long / cut off.** Select a very long text (for example 40,000 characters) and press PgUp.
   The toast says the text is too long, and nothing is replaced. If the model cuts an answer off,
   the "cut off" message appears and nothing is pasted.
4. **Malformed config.ini.** Add a second `model = x` line in `[qwen]` and save. After the reload a
   toast shows "config.ini: line N: 'model' appears twice in [qwen]" (once, not twice), and the app
   keeps working. Undo it.
5. **Broken prompts_user.py.** Tray, then "Edit prompts": Notepad opens `prompts_user.py`, starting
   with the explanatory header, with the whole `prompts.py` commented out. `prompts.py` itself is
   not opened.
   - Add a line `x = (` and save, then tray, then Reload. A warning toast mentions prompts_user.py,
     and actions still work with the standard prompts.
   - Delete the file afterwards.
6. **Duplicate and invalid keys (§7.2 item 5, C26).** In `config.ini [tasti]`, set
   `riassumi = PgUp` (the same as correggi) and save.
   - The startup toast says "Summarize: PgUp is already used by Fix, using PgDn". PgUp fixes and
     PgDn summarizes. The tray tooltip shows "PgUp fixes, PgDn summarizes, End explains".
   - Set `correggi = pgup`: the toast says it is not a valid key, using PgUp.
   - Set `correggi = PgDn` with no `riassumi` line: the toast says Summarize has no key, and the
     tooltip shows "(no key) summarizes".
   - Restore the keys. Then run §7.2 item 5 in the Settings page: duplicate and invalid keys are
     rejected there before saving, Shift+Tab is not captured, and a new key works after "Settings
     applied" without a restart.
7. **Flash restores progress (C27).** Start a long End job. While the progress toast shows, press
   End again: "Qwen is still working" appears for about 2 s, then the progress toast (with the
   current phase) comes back. The results page opens normally at the end.
8. **To-Do route failure.** Make the To-Do check fail (for example, a note whose reorganization
   would lose a link). The dialog listing the problems appears. While it is open, PgDn on a
   selection in Notepad still opens a summary.
9. **Health check quiet when fine.** With Ollama running and the model present, start AI-Hotkeys:
   no toast (or only "Settings applied" after a settings change).
10. **Display (§7.2 item 12).** At 125% and 150% scaling and with two monitors, a multi-line warning
    toast wraps (about 460 px of text), stays inside the work area of the monitor with the mouse,
    and does not take focus.
