# S14: Installer CI and draft-release workflow

New workflows `.github/workflows/installer.yml` and `.github/workflows/release.yml`. New helpers in
`scripts/ci/`:
- `InstallerTest.psm1`: install, uninstall, assertion and smoke functions
- `e2e-notepad.ps1`
- `fake_ollama.py`
- `get-sources.ps1` and `third-party-sources.json`

- actions are pinned by full SHA
- downloads are pinned by SHA-256
- scripts are Windows PowerShell 5.1 compatible, and the installer jobs run with `shell: powershell`

## installer.yml

**Triggers.** PRs and pushes touching any of:
- `installer/**`, `build/**`, `*.py`, `main.ahk`, `lib/**`, `static/**`, `actions/**`, `searxng/*.py`
- also the other payload or test inputs: `searxng/settings.yml`, `config.example.ini`, `VERSION`, `THIRD_PARTY_NOTICES.md`, `licenses/**`, `tools/licenses/**`, `scripts/ci/**` and the workflow itself

It can also be started manually (`workflow_dispatch`).

| Job | Runner | What it checks |
|---|---|---|
| build | windows-2022 and windows-latest | Runs `build\build.ps1` in full: clean tree, notices required, NSIS, H16 smoke. `build/cache` is cached, keyed on the hash of `pins.json` and `requirements-searxng.txt`; build.ps1 re-verifies every cached file. Re-checks `SHA256SUMS.txt`, then uploads the Setup exe, `SHA256SUMS.txt` and `manifest.txt` as `installer-<os>`. |
| reproducibility | windows-latest | `manifest.txt` must be identical between the two images (the S11 second-machine criterion). A different Setup.exe hash is only a warning. |
| install | both | See "install job" below. |
| upgrade | both | See "upgrade job" below. |
| upgrade-v1 | windows-latest | Runs only if the repository variable `V1_SETUP_URL` is set (D11: v1.0.0 is not on GitHub). It also needs `V1_SETUP_SHA256`, and the download is hash-checked. The job installs v1.0.0 to `C:\AI-Hotkeys`, modifies `config.ini`, then upgrades in place with `/D=`. Checks: no `config.esempio.ini`, no `python\Lib`, no Italian shortcuts, `config.ini` kept, plus the full install assertions. |
| e2e (H14) | windows-latest, `continue-on-error` | See "e2e job" below. |

**install job**
1. Rejected folders: `/D=C:\` and a folder inside the git checkout must exit with code 2 and write nothing.
2. Default folder `%LOCALAPPDATA%\Programs\AI-Hotkeys`: install, assert, then `/PURGE` uninstall.
3. Custom folder `/S /NOOLLAMA /D=C:\Temp Dir\AI Hotkeys Test`: install, then assert with an explicit ACL (inheritance off).
4. Smoke tests.
5. `/S` uninstall must leave only `config.ini` and `work\`.
6. Reinstall, then `/S /PURGE` must leave nothing.
7. No AutoHotkey or Python process is left.

**upgrade job**
1. Install, then customize the install:
   - modified `config.ini`
   - a `prompts_user.py`
   - a modified `prompts.py`
   - an obsolete file added to the old `.manifest`
   - stale `__pycache__` folders, including one in `work\`
2. Start `main.ahk` and `settings.py`, then install the same build over the running app.
3. Check:
   - all processes were stopped (C45)
   - `config.ini` and `prompts_user.py` were kept
   - `prompts.py.bak-<oldver>` was written (D4)
   - the obsolete file was removed (C30)
   - `__pycache__` was purged outside `work\`
   - the full install assertions pass
4. Uninstall with `/PURGE`.

**e2e job**
- Starts a fake Ollama on 127.0.0.1:11434: `fake_ollama.py` reuses `tests/support.py` FakeOllama.
- Sets `web_search = false` and starts the installed `main.ahk`.
- In Notepad: types a sentence, Ctrl+A, PgUp.
- Asserts that the fake received `/api/chat` and that the Notepad text became the fake's answer. The text is read back through the clipboard.
- Logs are uploaded.

**Assertions (`Assert-Installed`)**
- Every manifest file exists with its SHA-256. `.manifest` equals the build manifest.
- `Uninstall.exe`, `config.ini` and `work\` exist. `config.ini` equals `config.example.ini`.
- No developer folders are present.
- HKCU `InstallDir` and every uninstall-key value match: DisplayName, DisplayVersion, Publisher, DisplayIcon, InstallLocation, UninstallString, QuietUninstallString, URLInfoAbout, HelpLink, NoModify and NoRepair. EstimatedSize is plausible.
- The five `.lnk` files are resolved through WScript.Shell, with exact target and arguments, and both must exist. The desktop shortcut is absent (its section is off by default).
- ACL: no write-type ACE for Everyone, Authenticated Users or Users on the folder or on any file, checked by SID. A custom folder must also have inheritance disabled.

**Uninstall.** `Invoke-Uninstall` runs a copy of `Uninstall.exe` with `_?=<dir>`. This makes it run synchronously, gives its real exit code, and still lets it delete the folder.

**Smoke tests (`Invoke-InstalledSmoke`)**, all with the bundled Python and `-B`:
- import every app module, and assert isolated mode
- `viewer.py` and `settings.py` with `--no-browser`: 403 without the token, 403 with a wrong token, 200 with the right one. Printed URLs are redacted.
- `avvia_searxng.py --port <free> --work-dir <temp>`: `/healthz` must return 200 within 60 s
- only the process trees it started are killed

## release.yml

**Triggers.** A pushed `v*` tag, or a manual run.
- The job fails unless the tag equals `v` + `VERSION`.
- A manual run drafts `v<VERSION>` on the selected commit. It refuses if that tag already exists at another commit, or if a release for it already exists.

**Permissions.** Workflow level: `{}`. Job level: `contents: write`, `id-token: write`, `attestations: write`.

**Steps.**
1. Full `build.ps1`, with no cache.
2. `get-sources.ps1` downloads the AutoHotkey v2.0.19 source zip (new pin `5baa09e9…`, measured twice) and the SearXNG `6671d89` tarball (the `pins.json` pin). Both are hash-checked.
3. Stage `dist/`:
   - the Setup exe and `manifest.txt`, cross-checked against the build's SHA256SUMS
   - `third-party-sources.<name>` assets (release assets are flat, so the folder becomes a name prefix)
   - a regenerated `SHA256SUMS.txt` covering every asset
4. `actions/attest-build-provenance` on the exe, the manifest and the sources.
5. `gh release create --draft`, using `--verify-tag` for tag runs. The notes cover:
   - SmartScreen (unsigned build, D6)
   - checksum and `gh attestation verify`
   - the source offer
   - the first-release rollback note (reinstall the local v1.0.0)
6. The assets are also kept as a workflow artifact.

Publishing stays manual.

- PyYAML parses all three workflows. actionlint 1.7.12 (zip SHA-256 `6e7241b5…` matches the release checksums) reports no findings on `installer.yml`, `release.yml` and `ci.yml`.
- The PowerShell 5.1 parser finds 0 errors in every `scripts/ci/*.ps1` and `*.psm1` and in all 31 workflow `run:` blocks.
- `ruff check .` is clean. The unit suite passes: 207 tests OK (10 skipped, 1 expected failure).
- Against a throwaway `%TEMP%\aih s14 test\Inst Dir` copy of a built payload, with the current `avvia_searxng.py`:
  - all 4397 manifest hashes match
  - the ACL check passes (4801 items, 4 s)
  - the smoke tests pass: imports; viewer and settings return 403/403/200; SearXNG `/healthz` 200 after 3.1 s; no process left; no `__pycache__` written
- ACL negatives: a Users:(M) ACE on one file fails, and `-Protected` on an inheriting folder fails. An installer-style explicit ACL passes.
- `get-sources.ps1` passes both with and without the cache.
- `fake_ollama.py` answers `/api/version` and `/api/chat` (plain and NDJSON) and logs requests. It **refuses** 11434 while the real Ollama is listening there: `allow_reuse_address = False`, because SO_REUSEADDR on Windows would let it bind a busy port.
- **No installer or uninstaller was run.** The install, uninstall and E2E functions were not executed locally.
