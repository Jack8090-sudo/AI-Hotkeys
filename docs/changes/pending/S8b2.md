# S8b2 — main.ahk: process lifecycle

Fixes C18 (the orphan kill), C20 and C28 (launch flags). Reads contract K5 (S6c).

## User-visible

- **Reload and Exit no longer leave an orphan Python job (C18).** `OnExit` now runs
  `OnExitCleanup`: when a job is running it kills the job's process (`currentPid`) and removes the
  half-written `work\` files (`input.txt`, `output.txt`, `status.txt`, `meta.json`,
  `sources.json`), then stops SearXNG as before.
  - Exception: reason `"Single"` (a new copy of `main.ahk` replaced this one through
    `#SingleInstance Force`). The plan leaves cleanup to the new instance there, so the old job is
    not killed. The new instance cannot see the old `currentPid`, so that job can still finish and
    write `output.txt` (S9's work contract is the place to close this).
  - SearXNG is still left running on `"Reload"` and `"Single"`, as before.
- **Tray Reload and Exit ask first while a job runs.** "Qwen is still working. Reload anyway? The
  running job will be cancelled." Yes/No, with No as the default. With no job running, both act at
  once as before. The automatic reload after a config change was already deferred until the job
  ends; that is unchanged.
- **Exit never kills an unrelated program that reused SearXNG's pid (C20).** `StopSearxng` reads
  `work\searxng.pid` (K5: `<pid> <creation FILETIME>`, or the legacy `<pid>`) and kills the process
  only if:
  - its executable is the configured interpreter (`python\pythonw.exe`, or its `python.exe`
    sibling, since `websearch.py` starts SearXNG with the `pythonw.exe` next to `sys.executable`), and
  - for a K5 record, its creation time equals the recorded one. For a legacy record (no creation
    time), the full interpreter path must match. With a system `pythonw` (no bundled Python, so no
    folder to compare), a legacy record is never trusted.

  The pid file is deleted when it is unreadable, when the process is gone, or after the kill. If
  the pid is alive but does not verify, both the process and the file are left alone; the launcher
  removes its own pid file on a clean exit, and K5 readers ignore a stale one.
- **Python ignores the environment and the user site-packages (C28).** Every launch now uses
  `"<PYTHON_EXE>" -E -s`: the actions, viewer, settings, To-Do route, Free VRAM and the SearXNG
  launcher. The S11 build ships `python313._pth`, which already implies both, so they are redundant
  there but harmless (S11 note). `-B` was not added: the S11 installer deletes `__pycache__` on
  upgrade, which solves stale bytecode.
  - Side effect: `PYTHONUTF8`, `PYTHONIOENCODING` and every other `PYTHON*` variable no longer
    reach the app. The app opens its files with explicit encodings, so nothing depends on them.
  - Not covered here: `websearch.py` starts SearXNG with `subprocess.Popen` without `-E -s` (a
    Python-owned file). Under the shipped `._pth` the interpreter is isolated anyway; a
    Python-owning step can add the flags for parity.
- **File errors are reported, not thrown as raw AutoHotkey errors.** `try` now wraps:
  - writing `work\input.txt`,
  - deleting the previous `work\output.txt` and `work\obsidian_status.txt`,
  - reading `output.txt` and `obsidian_status.txt`,
  - starting the results page.

  Each failure shows "Could not write / delete / read <path>: <reason>" and stops the job. Before,
  an AutoHotkey error dialog appeared, with `busy` still set.

## Internal

- New `lib/Proc.ahk`, included by `main.ahk` and the test runner:
  - `ProcessCreationTime(pid)` returns the FILETIME from `GetProcessTimes` for a running process,
    or 0 when it has ended (even if a handle keeps it openable) or is not accessible.
  - `ProcessPathOf(pid)` returns `ProcessGetPath` or "".
- New pure helpers in `lib/Util.ahk`: `ParsePidRecord(text)` (same rules as
  `avvia_searxng.parse_pid_record`), `IsConfiguredPython(exePath, pythonExe)` and
  `SearxngPidIsOurs(record, exePath, ctime, pythonExe)`.
- `main.ahk`:
  - `PYTHON_EXE` (unquoted, used for the pid check) and `PYTHON` (`'"' PYTHON_EXE '" -E -s'`).
  - `FindPython()` now returns the unquoted path.
  - New `OnExitCleanup`, `ConfirmIfBusy` and `ShowError`. `ShowError` is still a modal MsgBox;
    S8b3 makes it non-modal.
- Tests: `tests/ahk/run.ahk` has 343 assertions, 0 failures. They cover:
  - K5 and legacy parsing, and malformed records,
  - the path and creation-time verdicts,
  - the creation time and path of the test process itself,
  - a child process that has ended reporting 0 / "".
- Cross-check, ad hoc: a bundled `python.exe` wrote its K5 record with `avvia_searxng`'s own
  functions, and `ProcessCreationTime` returned the identical FILETIME. Found on the way:
  `ProcessGetPath` returns the target of a directory junction. If the install folder is reached
  through a junction or symlink, the path check fails and SearXNG is left running on Exit, which is
  the safe direction.
- `/validate` was run on a copy outside the repo (exit 0). `main.ahk` itself was never run.

## Manual Windows E2E checklist (plan §7.2 items 7, 9 and 10, plus the S8b2 acceptance criteria)

1. **Reload during a job (C18).** Select a long text in Notepad and press End (explain, with web
   search, so it runs for a while). While the progress toast shows:
   - Tray, then Reload. The confirmation dialog appears. Choose **No**: the job continues and its
     results page opens normally.
   - Repeat, choose **Yes**. AI-Hotkeys reloads. In PowerShell:
     `Get-CimInstance Win32_Process -Filter "Name='pythonw.exe'" | Select ProcessId, CommandLine`.
     No `actions\explain.py` process is left. Only SearXNG (`avvia_searxng.py`) and any open
     results/settings page remain. `work\output.txt` does not appear afterwards.
2. **Exit during a job.** Same as 1 with tray, then Exit, then Yes. No `actions\*.py` process
   remains, SearXNG is stopped (`avvia_searxng.py` gone, `work\searxng.pid` gone).
3. **No job running.** Tray, then Reload, and tray, then Exit, act at once with no dialog.
4. **Stale pid (C20).** With AI-Hotkeys stopped:
   - Start an unrelated Python: `python -c "import time; time.sleep(600)"` (a system Python, not the
     bundled one). Note its pid.
   - Write `<that pid>` (legacy form) into `work\searxng.pid`. Start AI-Hotkeys with
     `web_search = false` (so SearXNG does not overwrite the file), then tray, then Exit. The
     unrelated Python is still running.
   - Repeat with `<that pid> 1` (K5 form, wrong creation time). Still running.
   - Kill it yourself afterwards.
5. **Normal SearXNG stop (§7.2 item 9).** With `web_search = auto`, start AI-Hotkeys, wait for
   `work\searxng.pid`, then tray, then Exit. SearXNG stops (`http://127.0.0.1:8888` no longer
   answers) and the pid file is gone. Tray, then Reload, keeps SearXNG running.
6. **Poisoned environment (C28).** Create `C:\poison\json.py` containing `raise SystemExit("poisoned")`.
   - `setx PYTHONPATH C:\poison`, then sign out and in (or start AI-Hotkeys from a shell with
     `$env:PYTHONPATH='C:\poison'`).
   - PgDn on a selection still produces a summary.
   - Also put a `json.py` that raises into the user site folder
     (`python\python.exe -m site --user-site`). PgDn still works.
   - Remove both afterwards.
7. **Esc (§7.2 item 7, I5).** A 2 s Esc hold during a job still cancels, kills Python and cleans
   `work\`. A short Esc still reaches the app.
8. **VRAM (§7.2 item 10, I10).** Tray, then "Free VRAM": `ollama ps` shows the model unloaded, and
   the toast says so.
9. **File error.** Make `work\output.txt` read-only and keep it open in another program that locks
   it (for example `notepad` will not lock it; use
   `$f=[IO.File]::Open('work\output.txt','Open','Read','None')` in PowerShell). Press PgDn on a
   selection. A "Could not delete the previous result …" message appears, and the hotkeys keep
   working afterwards. Close the handle (`$f.Close()`).
