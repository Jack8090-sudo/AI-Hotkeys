# S2 — CI baseline (GitHub Actions, Windows)

New `.github/workflows/ci.yml`, triggered on push and pull_request, with `permissions: contents: read`, a
`concurrency` group that cancels superseded runs, and `PYTHONDONTWRITEBYTECODE=1` / `PYTHONUTF8=1`.
Every action is pinned by full commit SHA (checked against the GitHub API on 2026-10-17):
`actions/checkout` v7.0.1, `actions/setup-python` v7.0.0, `actions/upload-artifact` v7.0.2.
Downloaded tools are checked against a pinned SHA-256.

## Jobs

| Job | Runner | What it does |
|---|---|---|
| lint | windows-latest | `ruff check .` (config in `pyproject.toml`); `python -m compileall -q` excluding `python/`, `searxng/app|lib|log`, `.claude/`, `build/cache|out`, `work/`, `graphify-out/` (`.pyc` go to a temp `PYTHONPYCACHEPREFIX`) |
| unit | windows-latest + windows-2022, Python 3.13 | `python -m unittest discover -s tests -t .`; the windows-latest leg runs it under coverage, enforces `--fail-under=72` and uploads `coverage.xml` |
| ahk-validate | windows-latest | Downloads AutoHotkey 2.0.19 per `build/pins.json`, verifies the SHA-256 and file version, then runs `/ErrorStdOut /validate main.ahk`, plus a negative test on `scripts/ci/fixtures/broken.ahk` that must fail |
| ahk-unit | windows-latest | Skipped with a notice until `tests/ahk/run.ahk` exists (S8a). After that it runs `/validate` on it and then runs it; the exit code is the failure count |
| secret-scan | ubuntu-latest | gitleaks 8.30.1 (pinned SHA-256) over the full history with `--redact`; `check_hygiene.py tracked` (no `config.ini`, `work/`, `*.exe`, `*.rar`); `check_hygiene.py paths` (no personal `C:\Users\<name>\` paths; placeholders such as `%USERPROFILE%`, `<name>` and `Public` are allowed) |
| licenses | windows-latest | `check_license_presence.py`: `LICENSE`, `ahk/license.txt`, `searxng/LICENSE-searxng.txt`, `static/fonts/OFL-*.txt` (one per shipped font family), the marked MIT header and `THIRD_PARTY_NOTICES.md`. It then runs `gen_notices.py --check` against a temp lib built from the hashed lock (`pip install --no-deps --no-compile --require-hashes --target`), so the vendored `searxng/lib` is not needed |
| vuln-scan | windows-latest | `pip-audit -r build/requirements-searxng.txt --require-hashes --disable-pip`. It is `continue-on-error` (advisory, H27) and must become blocking before release |

Helper scripts are in `scripts/ci/`: `pins.py`, `get-autohotkey.ps1`, `ahk-run.ps1`, `check_hygiene.py`,
`check_license_presence.py`, `coverage.ini`, `coverage_remap.py` and `fixtures/broken.ahk`. The PowerShell
scripts are 5.1-compatible.

## Coverage baseline

The tests import the app from a temp copy (`%TEMP%\aihk-test-*`), so the `[tool.coverage]` settings in
`pyproject.toml` (`source = .`) measure nothing ("No data was collected", 0%). CI therefore uses
`scripts/ci/coverage.ini` to measure the copies, and `coverage_remap.py` to map them back onto the repo
files.

Local baseline on 2026-10-17 (Python 3.13.16, branch coverage): **74.6% total**, so the ratchet is
`--fail-under=72`. Per file:

| File | Coverage |
|---|---|
| obsidian_todo | 90.9% |
| config_edit | 80.4% |
| pages | 79.8% |
| prompt_loader | 92.3% |
| prompts | 64.5% |
| qwen_client | 86.1% |
| settings | 90.3% |
| viewer | 75.3% |
| websearch | 52.0% |

Code run in subprocesses is not measured.

## Verified locally

- YAML parses with PyYAML, and actionlint 1.7.12 (SHA-256 verified) reports no findings.
- ruff and compileall are clean. The suite passes (7 expected failures).
- AutoHotkey 2.0.19 download: the SHA-256 and file version match. `/ErrorStdOut /validate` on a copy of
  `main.ahk` exits **0**; on the broken fixture it exits **2** and prints the syntax error. **H13 is
  confirmed** locally.
- gitleaks 8.30.1 over the full history: no leaks. The hygiene checks pass on 159 tracked files.
- License presence passes. `gen_notices.py --check` passes against the lock-installed lib. It fails
  against the old vendored `C:\AI-Hotkeys\searxng\lib`, which is expected: the notices follow the S11 lock.
- pip-audit on the lock: no known vulnerabilities.

## Only verifiable after the user pushes

- The jobs actually run on GitHub-hosted runners. In particular: H13 on CI (`/validate` exit codes on
  the runner image), the pwsh 7 behaviour of `ahk-run.ps1`, the windows-2022 leg, coverage path
  remapping with the runner's `%TEMP%`, and the coverage artifact upload.
- After the first green run, mark CI as a required check on `main` (branch protection; the user sets it up).
