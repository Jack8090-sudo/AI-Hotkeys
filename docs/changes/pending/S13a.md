# S13a: Installer location, permissions and legacy migration

Fixes **C09**. Implements **D1** and **D11**. Files: `installer/sorgente/installer.nsi`,
`installer/sorgente/legacy-1.0.0.manifest` (new) and `installer/sorgente/manifest.ps1` (new helper
next to `stop.ps1`, as the brief allowed).

## Build changes (S11 hand-off)

- `Target x86-unicode`. The official NSIS 3.11 only ships x86 stubs, and a 32-bit installer installs
  the x64 payload fine. `build.ps1` no longer needs `-NsisTarget`.
- `VERSION` comes only from `/DVERSION` (`!ifndef VERSION` → `!error`). `build.ps1` passes it, so its
  transitional `!ifndef` rewrite of the staged copy no longer triggers.
- `ManifestDPIAware true`.
- The installer embeds `manifest.txt` (staged next to `installer.nsi` by `build.ps1`) as
  `$PLUGINSDIR\new.manifest`, plus `manifest.ps1` and `legacy-1.0.0.manifest`.

## C09 / D1: install folder

- The default is `$LOCALAPPDATA\Programs\AI-Hotkeys`. It inherits the profile ACL: the user, SYSTEM and
  Administrators only.
- `InstallDirRegKey` was removed. `.onInit` reuses the registered folder only if it is not the v1.0.0
  default `C:\AI-Hotkeys` and still passes the folder rules. A `/D=` value always wins.
- `AihCheckDir` is called from `.onVerifyInstDir` (where it disables Next) and again at the start of
  the main section, because `.onVerifyInstDir` does not run for silent `/D=` installs. It rejects:
  - relative paths
  - drive roots (and UNC share roots)
  - a folder with `.git` in it **or in any parent folder**, which protects the repo at `C:\AI-Hotkeys`
  - folders that cannot be written. The test creates and deletes `aih-write-test.tmp` in the nearest
    existing folder: a file if the target folder already exists, a sub-folder if it does not (so a new
    `C:\Foo` is allowed even though users cannot create files in `C:\`). The result is cached per
    tested folder, because `.onVerifyInstDir` runs on every keystroke.
- `AihSecureDir`: a folder outside both `$PROFILE` and `$LOCALAPPDATA` gets an explicit ACL.
  - The user's SID comes from `"$SYSDIR\whoami.exe" /user /fo csv /nh`.
  - Then: `"$SYSDIR\icacls.exe" "<dir>" /inheritance:r /grant:r "*<SID>:(OI)(CI)F" "*S-1-5-18:(OI)(CI)F" "*S-1-5-32-544:(OI)(CI)F" /C /Q`
  - Then: `icacls "<dir>" /remove:g "*S-1-1-0" "*S-1-5-11" "*S-1-5-32-545" /T /C /Q`. This removes
    explicit grants to Everyone, Authenticated Users and Users in an existing custom folder.
  - SIDs are used instead of names, so localized group names and user names with spaces cannot break
    the command. Every tool is called by its full `$SYSDIR` path. Folders are normalized so there is
    never a trailing `\` before a closing quote.
  - It runs before any file is extracted, so every file inherits the ACL.
  - If whoami or icacls fails, the installer stops (error level 2) instead of installing into a folder
    other users can write.

## D11: v1.0.0 and other previous installations

- **`legacy-1.0.0.manifest`** was derived from the shipped `installer\AI-Hotkeys-Setup.exe`, which was
  listed and extracted to TEMP with 7-Zip (NanaZip 7z) and never run. The decompiled `[NSIS].nsi` was
  checked for the shortcut names and registry keys.
  - It lists 4883 files as `<sha256>  <path>`, the same format as `build/out/manifest.txt`. This
    includes `config.esempio.ini`, the `searxng\` tree (4270 files), the trimmed `python\` and
    `prompts.py` with its v1.0.0 hash, which D4 uses (S13b).
  - It omits `$PLUGINSDIR`, `[NSIS].nsi` and `Uninstall.exe`, which is written at install time.
  - It has six `shortcut  {programs|startup|desktop}/…` lines: `AI-Hotkeys.lnk`, `Configurazione.lnk`,
    `Modifica i prompt.lnk` and `Disinstalla.lnk` in the `AI-Hotkeys` Start-menu folder, plus
    `AI-Hotkeys.lnk` in Startup and on the Desktop.
  - v1.0.0 wrote `HKCU\Software\AI-Hotkeys\InstallDir` and the same uninstall key with
    `DisplayVersion 1.0.0`.
- **Migration.** It applies when the registered `InstallDir` differs from the chosen folder and still
  holds `main.ahk`. It runs before any file is extracted.
  - Interactive: a Yes/No MessageBox lists what will happen. With Yes, the installer:
    - runs `stop.ps1 -Dir <old>`
    - copies `config.ini` only if the new folder has none (I13)
    - renames `Uninstall.exe` to `Uninstall.exe.disabled-by-<new version>`, replacing an older
      disabled copy of the same name; on failure the user is warned not to run it
    - runs `manifest.ps1 -Action Shortcuts`, which deletes the listed shortcuts only if their target or
      arguments point into the old folder
    - tells the user the old folder was left in place and can be deleted. If the old folder contains
      `.git`, the message warns that it is a repository.
  - No: nothing in the old folder is touched.
  - Silent: only `config.ini` is copied.
- **In-place upgrade of v1.0.0.** This applies when `main.ahk` exists and either `config.esempio.ini`
  is present or the registry says `1.0.0` for this folder. The installer runs
  `manifest.ps1 -Action Upgrade` with legacy as old and the new build manifest as new, then
  `-Action Shortcuts`. `Upgrade`:
  - saves a customized `prompts.py` as `prompts.py.bak-1.0.0` (D4)
  - deletes the files in the legacy manifest that are not in the new one (`config.esempio.ini`, the
    old full `python\Lib`, `async_timeout`, …), then the folders this leaves empty
  - purges `__pycache__`
- **`manifest.ps1` safety.** It never deletes `config.ini`, `work\`, `prompts_user.py`,
  `prompts.local.py`, `prompts.py.bak-*`, `*.backup*`, `.manifest` or `Uninstall.exe*`. It ignores
  paths with `..`, `:`, `\` or a leading `/`. It refuses drive roots. It never follows reparse points.
  Exit codes: 0 ok, 1 partial, 2 bad input.

  working-copy `installer.nsi` was then compiled with the pinned makensis 3.11 against that staged
  `build\out`: **0 errors, 0 warnings**. (`build.ps1` compiles `git archive HEAD`, so uncommitted
  installer edits must be compiled this way.)
- PowerShell parser: 0 errors in `manifest.ps1` and `stop.ps1`.
- `manifest.ps1` was exercised in a throwaway `%TEMP%\aih mtest …\Inst Dir` tree (path with spaces):
  - `Upgrade` removed stale files and an emptied nested folder.

  - It ignored `../evil.txt` (exit 1).
  - It refused `C:\` (exit 2).
