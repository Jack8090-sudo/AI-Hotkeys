# S12 — Third-party license compliance

Fixes the documentation side of C29 (missing GPL/AGPL source offers, missing curl-impersonate/BoringSSL
notices, MIT `LICENSE` not shipped).

- New `THIRD_PARTY_NOTICES.md`. It covers AutoHotkey 2.0.19 (GPL-2.0, plus bundled PCRE), SearXNG
  `6671d89` (AGPL-3.0-or-later, plus its bundled web-client npm packages), CPython 3.13 (PSF, plus OpenSSL,
  libffi, SQLite, xz, expat, zlib, libmpdec and bzip2), curl_cffi 0.16.3 with libcurl-impersonate 2.2.2 (curl
  8.21.0, BoringSSL, nghttp2, ngtcp2, nghttp3, brotli, zstd, zlib), all 32 packages in `searxng/lib`, the
  native libraries statically linked into lxml/PyYAML/cffi, marked 12.0.2 and the OFL fonts. Ollama and
  the Qwen model (`qwen3.5:9b`, Apache-2.0 per the official model card) are listed as not redistributed.
  The file has a "not legal advice" note and a source-offer section: the AutoHotkey and SearXNG source
  archives are attached to every GitHub Release (implemented by S14).
- New `licenses/`: full license texts, each fetched from the upstream repository at the bundled tag or
  commit (npm packages without a matching tag come from the published npm package). The
  `licenses/python-packages/` subfolder is generated.
- New `tools/licenses/`:
  - `gen_notices.py --lib <searxng/lib> [--check]` builds the package table and copies the license files
    from `*.dist-info` metadata (also picking up license files vendored inside packages).
  - `check_notices.py <manifest> [--skip-shipped]` fails when a payload file, binary or package has no
    notice, when a pinned package version drifts, or when a notice file is missing from the payload.
    A binary (`.exe/.dll/.pyd/.so`) passes only if it is in its component's `binaries` allowlist or in
    its package's RECORD. A broad pattern such as `lib/**` therefore never waves an unknown DLL through.
  - `components.json` is the registry that maps payload paths to notices.
- Validation (2026-10-17, against the live vendored runtime):
  - `check_notices.py` passes on a sample manifest of `searxng\lib` and `python\` (4,804 files, with
    `--skip-shipped`) and on a full emulated `payload\{app,python,ahk,config.ini}` manifest (4,985 files,
    strict).
  - Negative cases fail as intended: unknown binaries inside covered folders (`lib/`, `ahk/`,
    `licenses/`, `searxng/app/`, `python/Lib/site-packages/`, an extra DLL in `lxml/` or
    `curl_cffi.libs/`), a new package (colorama), curl_cffi or lxml version drift, `LICENSE` not shipped,
    malformed lines, and a non-UTF-8 manifest (exit 2). A UTF-16 manifest from PowerShell 5.1 is accepted.
  - `gen_notices.py` reports missing Name or RECORD, declared license files that don't exist, `UNKNOWN` or
    non-SPDX licenses, unsafe `License-File` values, and native libraries without notices.
  - Reviewed by an `ecc:python-reviewer` agent. All 8 findings (1 HIGH, 4 MEDIUM, 3 LOW) were fixed and
    re-tested.
  - `gen_notices.py --check` is clean, and `ruff check tools/licenses` is clean.

## For S11 (build pipeline)

- Run `python tools/licenses/check_notices.py build/out/manifest.txt` after writing the manifest. Treat a
  non-zero exit as a build failure unless `-AllowMissingNotices` is set.
- **S11 adds `colorama 0.4.6` and moves to the CPython 3.13.16 embeddable package.** After the first
  pinned build, run `python tools/licenses/gen_notices.py --lib payload\app\searxng\lib` and commit the
  result. Until then, the check fails on colorama on purpose. (Its license override, BSD-3-Clause, is
  already in `components.json`.) OpenSSL 3.5.9 in 3.13.16 uses the same license text, which was verified.
- Manifest paths may be payload-relative (`app/...`, `python/...`) or install-relative. The checker
  strips a leading `payload/` and `app/`.
- If the payload gains a file type not listed in `components.json` (for example `lib/*.ahk` once S8a
  lands, which is already covered by `lib/**`), the check fails until a pattern is added.

## Left for user review (not legal advice; please read before release)

1. **Source-offer wording (§1).** The file promises source archives on every Release, and fulfilment on
   request through a GitHub issue if one is missing. Confirm you are willing to make that commitment.
2. **SearXNG modification status (§4).** S11's H17 diff decides whether the vendored `searx/` is
   unmodified. If S11 records changes, add the patch to §4 and to the Release assets.
3. **libiconv (LGPL-2.1) inside lxml's `.pyd` files.** lxml's own `LICENSES.txt` says its wheels bundle
   libiconv under LGPL-2.1. The notice relies on the `.pyd` files being separate, unmodified, replaceable
   files, and links the lxml and libiconv sources. Decide whether that is enough for you, or whether to
   also attach the lxml 6.1.3 sdist and libiconv 1.18 sources to each Release.
4. **SearXNG web client.** The npm packages were identified from the shipped source maps (OpenLayers,
   mathjs, @babel/runtime, typed-function, escape-latex, tiny-emitter, quickselect, rbush, swiped-events),
   plus ionicons and normalize.css from `package.json`. Their texts are in `licenses/searxng/frontend/`.
   `searx/data/` datasets are covered only by reference to the SearXNG source.
5. **SQLite version.** The `sqlite3.dll` in the current `python\` reports source id `2025-02-18`, while
   CPython 3.13.7's `get_externals.bat` names 3.50.4. SQLite is public domain, so the notice gives no
   version.
6. **Qwen model license.** Apache-2.0 was taken from the official `Qwen/Qwen3.5-9B` Hugging Face card,
   because the Ollama library page names no license. Re-check if the default model changes.
7. **README link.** S15 owns `README.md` and should link `THIRD_PARTY_NOTICES.md` and mention the source
   archives.
