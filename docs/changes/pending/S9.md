# S9 — work/ contract hardening, privacy and error mapping in the viewer

Fixes C32, C21, H04, and the orphan-overwrite part of C18. This step changes the K1 `error.txt`
location and adds a new form of the K3 viewer command line. The old form still works.

## User-visible (privacy)

- **The selected text no longer stays on disk (C32).** Each PgUp/PgDn/End job gets its own folder,
  `work\runs\<run id>\`. The run id is the local time (`yyyyMMddHHmmss`), `-`, then 16 random hex
  digits. The folder holds `input.txt` (the selection), `output.txt`, `meta.json`, `sources.json`,
  `status.txt` and `error.txt`. The folder is deleted:
  - by the results page (`viewer.py`) as soon as it has loaded the files, before it serves the page.
    The text then lives only in the viewer's memory until its idle shutdown;
  - by AutoHotkey after a successful direct replace, after any error, and after an Esc cancel (I5);
  - by `OnExit` (Reload, Exit, and also `#SingleInstance` replacement) for the running job.
- **Crash leftovers are swept.** Run folders not modified for 1 hour are deleted at startup and
  before each job, by AutoHotkey and by Python (`qwen_client.sweep_stale_runs`). Only folders named
  like a run id are touched.
- **Leftovers of older versions are removed at startup:** `work\input.txt`, `output.txt`,
  `status.txt`, `meta.json` and `sources.json`.
- **`work\` is private to the user.** At first start, a best-effort ACL is applied with `icacls`.
  Full control goes to the current user (`%USERDOMAIN%\%USERNAME%`), SYSTEM and Administrators.
  Administrators are kept so backups and an elevated uninstaller with `/PURGE` still work.
  - Inherited entries are removed only after the grant succeeded, so a failure cannot lock the user
    out.
  - The attempt and its result are recorded in `work\acl.done`, and it is not retried. Delete that
    file to retry.
- **Two jobs back to back show the right pair (H04).** The results page of an earlier job reads its
  own folder, so a newer job can no longer swap in its input or output.
- **An orphaned job cannot affect a newer one (C18).** A job writes only into its own run folder,
  and never creates it. If AutoHotkey deleted the folder (Esc, Exit, Reload, or a `#SingleInstance`
  replacement), the late result is simply dropped. Nothing is recreated and no plaintext is left.
- **Follow-up errors are specific (C21).** In "Ask Qwen", a missing model now says
  "Model '…' not found: run  ollama pull …" instead of "Cannot reach Ollama". All follow-up failures
  go through `qwen_client.describe_error` (K1). The "cut off" and "interrupted" messages are
  unchanged.

## Contract changes

- **Actions:** `actions\<action>.py --run-dir=<work\runs\id>` (new; `main.ahk` uses it).
  `<script> <input.txt> <output.txt>` still works and writes to `work\` exactly as before.
- **K1 location:** jobs started with `--run-dir` write `error.txt` inside the run folder. `main.ahk`
  reads it there (`ReadErrorLine(runDir "\error.txt")`).
  - `work\error.txt` stays for the health check, Free VRAM and the old argument form.
  - The S8b3 race (the health check's `clear_error` deleting a failing job's `error.txt`) is gone.
- **K3 viewer:** `viewer.py --run-dir=<dir> "<name>" <mode> [--key=…] [--no-browser]` (new).
  `viewer.py <input> <output> "<name>" <mode> …` still works.
  - New form: the run folder is deleted after loading, but only if it is directly inside
    `work\runs` and named like a run id.
  - Old form: input and output are deleted after loading only when they are inside `work\`. Files
    elsewhere are never deleted.
- **Atomic writes:** in run folders, `output.txt`, `meta.json`, `sources.json` and `error.txt` are
  written to a temp file and then renamed. `meta.json` is written before `output.txt`.
  `status.txt` keeps its plain write.
- **Unchanged:** `work\config_warning.txt` (K6), `work\searxng.pid` (K5) and
  `work\obsidian_status.txt` / `obsidian_output.txt`. The To-Do route does not use run folders.
  `obsidian_output.txt` is already deleted on success and kept only when a check fails, because the
  message points to it.

## Internal

- `qwen_client`: `RUNS_DIR`, `RUN_ID_RE`, `STALE_RUN_SECONDS`, `parse_action_args`, `is_run_dir`,
  `sweep_stale_runs`, `remove_run_dir`. `_write_atomic(..., create_dir=False)` refuses to create a
  missing run folder. `write_error` and `clear_error` follow the current run.
- `websearch.save_sources(..., path=None)` / `load_sources(path=None)`: now atomic, with an optional
  path. For an explain job, `run_action` points `websearch.STATUS_FILE` at the run folder.
- `viewer`: `load_run(argv)` parses both forms, loads, then deletes. `Session(..., sources=None,
  meta=None)` and `read_meta(path=None)` are backward-compatible.
- `lib/Util.ahk`: `NewRunId`, `IsRunId`, `RunDirOf`, `RunIsStale`, `WorkAclArgs` (pure).
- `main.ahk`:
  - `RunSelectionAction` creates the folder and owns its deletion (`try/finally`). The job itself
    is in the new `RunCapturedJob`.
  - New `DeleteRunDir` (it refuses anything that is not `work\runs\<run id>`), `SweepRuns`,
    `LegacyWorkCleanup` and `SecureWorkDir`.
  - `OpenResultsPage(action, keyLbl, runDir)` returns whether the viewer started.
  - `CleanupWorkFiles` is replaced.
- Tests:
  - `tests/test_work_contract.py` (16 tests). They cover the writers, K1 in the run folder, the
    orphan, the sweep, C32 end to end, H04 end to end, and the old argument form for both actions
    and the viewer. Actions and the viewer run as subprocesses against FakeOllama.
  - `test_C21_*` is no longer an expected failure.
  - `tests/ahk/run.ahk`: 422 assertions, 0 failures.
  - Python: 224 tests OK. `ruff` is clean.
  - `/validate` was run on a copy outside the repo (exit 0). `main.ahk` itself was never run.

## Manual Windows E2E checklist (plan §7.2 items 2, 3, 7, 8 and 11)

Keep Explorer open on `work\` (show hidden files) during these checks.

1. **Default keys (§7.2 item 2).** Run these in Notepad, Notepad++, VS Code, Word and Obsidian.
   - PgUp replaces the text (I6). Immediately afterwards, `work\runs\` is empty.
   - PgDn opens the summary page, and End opens the explanation page with sources. Both pages show
     the right original and result. Within a second of the page opening, `work\runs\` is empty
     again.
   - In a follow-up on the End page, the sources are still cited (I7). They are kept in memory.
2. **Back to back (H04).** Select text A and press PgDn. As soon as its page opens, select text B
   and press PgDn. Each page shows its own original and result (A with A, B with B).
3. **Nothing selected (§7.2 item 3).** PgUp, PgDn and End act natively with no stall, and the
   clipboard is intact. No folder appears in `work\runs\`.
4. **Esc (§7.2 item 7, I5).** Start a long End job and hold Esc for 2 s.
   - "Cancelled" appears and no `pythonw` action process remains.
   - `work\runs\` is empty, and no `output.txt` appears later.
   - A short Esc still works in the app.
5. **Exit or Reload during a job (C18).**
   - Start a long End job, then use the tray: Reload, then Yes. `work\runs\` is empty, and stays
     empty after the old job's time would have elapsed.
   - Repeat, but replace the running copy by starting `main.ahk` again (`#SingleInstance`). The
     old job may keep running, but its folder is gone and no file appears in `work\` or
     `work\runs\`.
6. **Results page (§7.2 item 8).**
   - Themes and colours work.
   - Follow-up questions stream and can be stopped.
   - Copy works.
   - Remote images are not loaded.
   - The idle shutdown happens at about 4 min, and the disconnected banner appears.
7. **Errors (§7.2 item 11).**
   - With Ollama stopped, PgDn shows "Ollama is not running…", and `work\runs\` is empty afterwards.
   - With `model = qwen-does-not-exist`, PgDn shows "…run  ollama pull…". Then open any results
     page (with the real model restored) and stop Ollama's model, or set the wrong model and ask a
     follow-up: the follow-up error mentions `ollama pull`, not "Cannot reach Ollama" (C21).
   - A long selection gives the "too long" or "cut off" message, and nothing is replaced.
   - A malformed `config.ini` shows a warning toast.
8. **Permissions.** After the first start, `icacls work` lists only you, SYSTEM and Administrators,
   with no `(I)` inherited entries, and `work\acl.done` says `ok`. Another standard user cannot open
   `work\`.
9. **Stale sweep.** With AI-Hotkeys stopped, create the folder
   `work\runs\20200101000000-0123456789abcdef` and a folder `work\runs\keepme`, then start
   AI-Hotkeys. The first is removed. `keepme` stays, because its name is not a run id.
10. **Upgrade.** With an old `work\input.txt` and `output.txt` present, start AI-Hotkeys: both are
    deleted.
